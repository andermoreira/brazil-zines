Logando e comandos simples.
-------------------------------

    Bem-Vindo à Hacking Dec 10's!

    Existe um jeito de reconhecer um Dec 10, vc vai receber o prompt ".". Primeiro, vai ter uma pequena mensagem de login, como o login em uma BBS. Por Exemplo:

NIH Timesharing 

NIH Tri-SMP 7.02-FF 19:57:11 TTY12

system 1378/1381/1453 Connected to Node Happy(40) Line # 13

Please LOGIN
.

    Agora, vc foi tão longe que encontrou um Dec(Digital Equipment Corp), vc vai precisar saber o formato do login.

[Login Format]

    Os usuários têm números chamados PPN's, que significa "Project/Program Number". O formato do PPN é [X, X]. O 1o. número é o do project e o segundo, do programa.
    Exemplo --

.Log 12,34 

Job 64 NIH 7.01 KL 64-UC TTY12

Password:

    A senha varia de 1 a 8 caracteres, pode ter números, iniciais ou algo do tipo. Tente e pense, se eu fosse um usuário, qual seria minha senha? Eu duvido que este método funcione, mas vale a pena tentar.

    Vamos dizer que essa é a sua primeira vez em um Dec 10. Se vc quiser ver algumas informações sobre o sistema e alguns comandos, vc pode digitar--

.Help

    Isto vai lhe dizer um pouco mais sobre o sistema que vc está usando. Vai te ensinar como pegar informações sobre um tópico específico. Ele pode também dar o número de voz, caso vc tenha problemas. Agora, o telefene de voz pode te ajudar se vc for bom em BBS'ing. Normalmente, o comando Help vai falar para vc consultar o "Dec-10 System Guide" para maiores informações.

    Agora, vc quer uma lista de comandos que podem ser executados. Digite --
. Help *

    Vc vai, então, receber os seguintes comandos- que são muitos para serem digitados, mas vc vai reconhecer qdo digitar Help *.

    Depois que ele mostrar todos os comandos, ele vai te ensinar a "logar". Ele não vai te dar uma conta de demonstração, mas vai dar um exemplo de login.

    Ele vai falar algo como, "O comando de login é usado para acessar o sistema timesharing Decsystem-10".

    Para "logar", o seu número de Projeto e Programa.

    LOGIN XXX, XXX

    O sistema vai te pedir a senha. Se o seu PPN ou senha estiver errado, vc vai receber uma mensagem que diz --

Enter Project,programmer #xxx,xxxx

Password:

--Fim.--

    Agora, vc pode acessar outros comandos útes, mesmo sem a conta. Vc pode Decnet, que eu discutirei mais tarde e é muito interessante ppara uum hacker.

    Agora, existe um programa que vc pode executar, chamado "Help Phone". A única coisa que ele faz é listar os números dos Decs, etc... Exemplo--

.Help Phone 

DCRT/CCB/DECsystem-10 Information Phone numbers (4/86) 

Recorded message Dial xxx-xxxx
Dec-10 operator Dial xxx-xxxx
Dec-10 staff Dial xxx-xxxx
Terminal Repairs Dial xxx-xxxx
Classes/Courses Dial xxx-xxxx
Users Area Phone Dial xxx-xxxx
Project Control Office Dial xxx-xxxx

NOTE:This is the same area code as the Decsystem.

    Agora, os 2 números mais importantes são os do Operadores do Dec-10 e da equipe do Dec-10.

    O comando mais importante que pode ser usado no Dec-10 é o "Systat"; ele vai mostar todos os PPN's, hora, processos, tempo determinado.
    Assim que vc pegar um PPN, vc pode começar a hackear. Usar Systat é o meio fácil e simples de pegar PPN's. Vai ser mas fácil digitar só "SY", ao invés de "Systat".

    Um pequeno exemplo do que vc vai pegar usando systat.

.SY 

Status of Brown University 603A at 11:52:33 on 29-Jan-86 

Uptime 187:12:22, 80%Null time = 80%idle + 0%Lost

7 Jobs in use out of 128. 19 logged in 4 detached out of 89 (LOGMAX)

Job Who What Run Time 

1 [OPR] OPSER 3:22
2 [OPR] DIALOG 1:29
3 [OPR] BATCON 4:01
4 [OPR] SYSINF 51:13 01
5 24,2 SYSTAT 4:52
6 2332,21 DIRECT 2:22
7 32,22 SYSTAT 8:19

    Vai aparecer mais coisa junto disso. Agora, vc não deve se preocupar com isso, por esse motivo eu não coloquei acima. Também aparecerá mais "subheadings" além do "runtime", "who", "what" e "job". Vc tb não deve se preocupar com isso.

    Tudo o que está acima é bem auto-explicativo. Para os iniciantes que estão lendo este arquivo, vou falar que o que os "Jobs"(Trabalhos, Serviços) significam não é de importância. "Who" está te dizendo que tipo de usuário está no sistema. [OPR] significa Operator e os números, como 24,2, referem-se a usuárrios comuns com PPN's. "What" diz o que o usuário está executando ou fazendo no ato do comando. "Run Time" fala que horas o usuário entrou no sistema. Eles usam a hora militar. No systat vc pode encontrar: Estrutura do Sistema de Arquivos, Dispositivos Ocupados, Segmentos de Altura e Estrutura do disco. Por enquanto, não se preocupe com nada disso.

    Agora vc finalmente encontrou alguns PPN's e a primeira coisa a fazer é "logar" com o procedimento mostrado com Log. Entre com o PPN xx, xx e tente descobrir algumas senhas.

    Eu vou te dar uma lista de senhas que eu usei para entrar num Dec10. Se as senhas não funcionarem, me dsculpem mas vcs terão que procurar sozinhos.

    Nota: vc pode fazer um programa que teste os PPN's e senhas.

Lista de Senhas--
-------------------------------------
Sex            Dec             Decnet
Games       Test             Dcl
System       Computer   Password
Help           Link            List
Secret        Default        Mode
Account     Terminal    Acsnet
Ppn            Operator    Connect
-------------------------------------

    As pessoas muito mais senhas além dessas, mas essas são as mais comuns.
    Vc pode tentar senhas aleatórias tb. Tais como: AA, AAB, AB, CC, etc...

    Isso é o suficiente para se "logar". Eu gastei um pouco demais de tempo nisso, mas como este vai ser um arquivo de duas partes, eu discutirei mais comandos na parte II. Este arquivo é destinado a iniciantes então, os Dec Hackers experientes estão chateados agora ou ficarão mais tarde.

    Nota: Se vc se conectou à Acsnet, digite AcsDec10 para acessar o Dec. Todo o resto que eu mencionei nologin, vai funcionar.

    [No Sistema]

    Agora, nós assumimos que vc finalmente entrou no sistema depois de bagunçar todo o seu cérebro. Deste modo vc saberá que está no sistema. Exemplo--

.Login 21, 34
Password:

    Nota: Vc tem duas tentativas para acertar o PPN e a senha.

    O Dec vai se apresentar dizendo quando vc entrou pela última vez   e etc.

    Vc tb pode fazer algo assim para entrar:

.Log 12,34
JOB 51 NIH 7.01 KL 64-UC TT12
Password:[c/r]
Other jobs detached with same PPN:
Job 34 running SYSTAT in ^C state
Do you want to ATTACH to this job? yes 

Attaching to job 34

    O que vc está fazendo agora é se anexar a um PPN ocioso. Veja, enquanto alguém está no sistema, 10mins (15mins=max) antes de vc, ele pode entrar com um comando que permitirá que eles saiam do sistema e depois se anexar novamente àquele PPN quando voltar. Esta pessoa será colocado no lugar exato em que ele saiu do sistema. Se eu estivesse usando 'sys' e saísse do sistema, eu usaria o comando 'detach'. Agora a pessoa tem 15 mins para voltar e anexar a seu PPN. Se a pessoa passar um determinado tempo sem digitar nada, ela vai ser desconectada e se vc ligar nos próximos 15 mins vc pode conseguir se anexar a este PPN.

    Nota: Vc ainda poderá ter que logar.

    Ok, agora nós estamos no sistema depois que ele se verificou. O que faremos? Primeiro, vamos dar mais uma olhada no 'systat'. Nós percebemos que tem uma outra pessoa no sistema. Mas nós vemos que ele está em 'exe', isto significa que ele não está fazendo nada ou está desanexado. Em outras palavras, não se preocupe.

    Se nós quisessemos mudar a senha nó digitariamos--

/Password

    Depois que nós fizermos isso, o sistema vai pedir pela antiga e nova senha. Mas nós devemos deixá-la do jeito que está para não sermos descobertos. É bom saber.

    Agora, nós podemos olhar os arquivos dos outros usuários. Digite--
Dir [*,*]

* = Coringa

    Isso vai mostrar os arquivos de usuários que permitem que todos vejam o seu diretório. Vamos dizer que vc queira ver os arquivos de alguém específico. Nós digitaríamos--

Dir [12,11]

    Se 12, 11 é  número que queremos, devemos digitar entre os colchetes.

    Existem vários tipos de arquivos. Vc deve ter olhado aos diretórios de outra pessoa ou listar pelo coringa e viu um monte de arquivos. Na maioria dos arquivos vc deve ter visto as palavras 'txt' e 'exe'.

    Para exe, vc digitará-

[PPN] nomedoarquivo.exe

    Para txt, vc digitará-

type nomedoarquivo.txt

    Vc tb pode ver arquivos como: dat, bas, cmd, pcl, bin, hlp e alguns outros.

<1>Exe = Executável - significa que vc pode rodar estes arquivos a partir do promp "."

<2>Txt = Texto - São arquivos de texto que podem conter: informação, dados ou outro tipo de coisa. São arquivos que vc verá na maioria dos diretórios públicos e é o mais popular em Dec10's.

<3>Bas = Basic - Estes arquivos são escritos em basic e deve ser usado em basic. Para rodar em um Dec-10, digite Run Bas e se não funcionar digite no velho basic.

    Nota: Os arquivos basic devem ser usados como qualquer outro arquivo básico. Carregue-os e e rode-os.

    Estes são os arquivos mais comuns que vc pode encontrar. Qdo vc for mestre nestes tipos de arquivos, vc pode ver os outros tipos de arquivos.

    Outro meio de ver os arquivos é digitando--

File:[*,*]<comando>
Mais uma vez, o '*' é o coringa.

[Criando um diretório]

    Para criar um diretório vc pode digitar, no prompt principal, 'Credir'. Existem 2 níveis para um diretório. O primeiro nível é Class e o segundo Tvedit.

    Digamos que nós temos uma bela conta privada e podemos criar um diretório de 2 níveis. Nós digitaríamos--

Create Directory:[,,class,tvedit] 

    O Dec10 responderia falando--

Created Dska0:[x,x,class]Sfd/protec:775
Created Dska0:[x,x,class,tvedit]sfd/protec:755 

    x,x= O PPN que vc está usando e Dska0 é o dispositivo-

    Nós podemos nomear o diretório digitando--

/Name:<o nome que vc quiser> 

    Nota: Vc não precisa dos sinais <>

    Nós podemos protegê-lo digitando--

/Protect:<nome> 

    Existem mais comandos '/'. Vc pode ver quais são digitando '/help'. 

    Chega de diretórios

 

[Privilégios]

    O que a maioria dos hackers querem ao entrar em um sistema, é uma conta com privilégios. Se nós tivermos uma conta com privilégios, nós podemos criar a própria conta e outras coisas que valem a pena. Em um Dec10, quase todas as contas privilegiadas começam com um 1. Ex- 1,10. Nós podemos checar o estado do sistema(sys) e ver se tem alguém com uma conta 1,x. Se tiver, nós podemos começar a hackear a senha. Agora, se vc entrar sob '1, 2', é uma outra história. Vamos dizer que nós pegamos uma conta privilegiada. A primeira coisa a fazer para ativar os privilégios é digitar 'enable', isso vai nos dar um prompt '$' ou '#'. Não importa qual. Nós ainda podemos fazer o que quisermos. Digamos que nós queremos fazer uma bela conta, digitaríamos--

$Build[x,x] or Create[x,x]

    Depois que fizermos, podemos editar o PPN ou, se for novo, criar o seu próprio. Agora, eu deveria ter falado antes, mas se vc entar em uma conta 1, x, certifique-se de que não tem ninguém na mesma conta que vc. Se tiver, ele pode mudar a senha e e mesmo se ele estiver em 'exe' e "desanexado", nós não queremos correr nenhum risco. Eu sugiro que vc ligue tarde da noite ou bem cedinho ou se vc tiver chegado em casa depois da escola, ligue mais ou menos meio-dia.

    Existem vários tipos de privilegiados, os operadores, "wheel" e CIA. O CIA é o nível mais alto e vc pode fazer tudo e qualquer coisa. Se vc tiver privilégios de operador vc pode fazer o que está acima sem problemas. Isso também vc vai ser bom qdo vc quiser entrar na Decnet.

    Se vc fizer uma conta privilegiada, vc deve digitar--

    Help Phones < como mencionado anteriormente>

no prompt principal. Vc vai receber uma lista de números de telefone, incluindo o do operador e gerenciador. Eles estão normalmente abertos das 10am às 5pm. Ligue neste horário e pergunte se vc pode ter um "Decsystem Timesharing Guide". Eles irão perguntar qual o seu nome, PPN e senha. Se ele perguntarem pq vc ainda nãoo recebeu um, diga que vc "arranjou" uma senha e nunca foi informado do manual.

    Este manual é muito útil. Ele vai te ensinar comandos, explicar detalhadamente, novas características, jogos, etc. Não peça pelo manual no dia que vc criou a sua conta, espere por uns 4 dias e daí, ligue. Eles normalmente mandarão no dia seguinte. É seguro mandá-lo para a sua casa, mas se vc não se sentir bem, mande para um outro endereço.

[Subsistema de Correio]

    Talvez vc conheça algum amigo que tenha uma conta no mesmo Dec10 que vc. Seu amigo pode não estar no sistema agora, isso elimina as chances de mandar mensagens para ele. Mas existe uma alternativa que é mandar um Mail para ele. Com o Mail vc precisará do nome da pessoa. Para acessar o Mail, digite--

Run Mail

    Vc receberá o promp 'MailC', neste prompt vc digita--

MailC:Send

    Agora vc receberá perguntas de para quem vc quer mandar o Mail. Vai ser algo assim:

.Run Mail
MailC:Send

to:Death Hatchet
Subject:Disk Crash
Text:

Yo! My file disk got ruined with //e Writer. See ya.

    Quando vc acabar com o seu texto, digite '.done' ou '.d' numa linha em branco para indicar que vc acabou. O Dec10 vai responder dizendo-

Death Hatchet--Sent

- e retornará ao prompt 'MailC'. Se vc quiser mandar a mesma mensagem para duas pessoas, vc faria a mesma coisa que acima , exceto que no 'to:', vc digitará-

To:Death Hatchet,The Rico

    A única diferença é a vírgula. Vc DEVE digitar a vírgula para separar os dois nomes, senão o sistema vai pensar que é tudo um nome só. Uma vez que o mail foi mandado, o usuário Death Hatchet irá receber qdo entrar no sistema. Depois que ele receber as mensagens de boas-vindas e o seu estado desde a última vez que ele entrou, o mail será automaticamente lido por ele assim-

From:Carrier Culprit                              Postmark:20-Mar-86-08:12:27
to:Death Hatchet
Subject:Disk Crash

Yo! My file disk got ruined with //e Writer. See ya.

    Ele lerá o resto do mail se tiver mais alguma coisa. Se não, ele vai para o prompt principal. Se vc quiser ler o mail novamente, vá para a seção do mail e digitar 'read' ao invés de send. Vc poderá gravar para a sua próxima chamada ou eliminá-lo. Às vezes o mail não aparecerá no momento que vc se conectar então, vá para a seção de mail e verifique se for o caso.

    Em algumas versões antigas do Dec10, o mail não era usado e vc só podia mandar mensagens. Mail foi adicionado ao Dec10 no meio dos anos 70. Não é importante, mas é bom saber. Se vc digitar 'run mail' e não for à parte de Mail, tente 'run mai'. O 'run mai' é usado em alguns sistemas mais antigos, mas normalmente o sistema entende os dois.

    Nunca mande Mail violentos aos operadores, senão eles vão te desconectar e literalmente ACABAR com a sua conta. Se vc for fazer isso, eu sugiro que vc tenha um outro PPN à mão. Em alguns dos Dec10's mais modernos, vc pode redirecionar emails, digitando 'Frd Mail' no prompt 'MailC'. O sistema vai pedir para quem vc está mandando, a sua senha e a do receptor. O operador do sistema checa a informação com os dois lados e ele vai deixar te deixar um mail dizendo que ele mandou. Isso ainda está sendo testado, mas eu já vi em operação em alguns Dec10's em 714.

    Este é outro programa que "vem a calhar" e que pode ser usado para tirar vantagem. Ele te dá informação sobre trabalhos e PPN's. Vc não consegue as senhas, mas pode conseguir umas belas estatísticas. Se vc digitar 'info' ou 'Help info', vc receberá uma lista como a seguinte-

    E a lista continua. Se vc quiser ver toda a lista, digite 'Help Info'. Ele tb vai te informar sobre os dispositivos de disco, diretórios e outras coisas. Alguns dos Dec10's não suportam isso, mas a maioria sim.

    O '1, 2' que está próximo ao operador são contas do operador do sistema. Eu mencionei isso antes, para que vc não se confundisse. A maioria doas arquivos são supervisionados por esta conta. Se vc conseguir entrar em uma dessas, vc terá muito o que fazer... hehehehehehe.

[Watch]

    Este comando irá lhe mostrar as suas estatísticas. Vc poderá mudar isso. Vc pode ligar, o que irá mostrar no topo da sua tela, ou olhar para isso só uma vez. O 'watch' mostrará--

Run---significa o tempo da sua CPU.
Wait--significa o tempo estimado desde o começo.
Read--número dos blocos do disco que vc leu.
Write--número de blocos do disco que vc gravou.

    se vc tiver privilégios no sistema, digite--

[XX, XX]

ARPANET

    A ARPANET, que é o principal componente da NSFNET(National Science Foundation Network), começou em 1969 como um projeto "R&D" gerenciado pelo DARPA(Dept . of Defense Advanced Research Projects Agency). A ARPANET era uma experiência em compartilhamento de recursos e oferecia links de comunicação de alta banda-larga (56kb/s), entre os principais recursos computacionais e usuários de computador em laboratórios de pesquisas de faculdades, indústrias e governamentais. A ARPANET é gerencia e foi fundada pela DCA(Defense Communications Agency), com seviços para usuários oferecidos por uma rede central de informação na SRI International.

    A ARPANET serviu como um teste para o desenvolvimento de protocolos avançados de rede, incluindo o TCP-IP apresentado em 1981. O TCP-IP e particularmente o IP, o protocolo da internet, apresentou a idéia de "inter-networking" --- permitindo que redes de diferentes tecnologias e protocolos de conexão sejam juntados de maneira a oferecer um esquema unificado de endereçamento e um jeito comum de transporte de aplicações e protocolos. Este desenvolvimento permitiu que redes de computadores e workstations se conectassem à ARPANET, ao invés de se conectar a apenas um computador host. TCP-IP ainda é o protocolo de rede mais avançado disponível e influenciou fortemente os padrões internacionais atuais de atividade. TCP-IP oferece uma variedade de serviços de aplicação, incluindo logon remoto(Telnet), transferência de arquivo(FTP) e email(SMTP e RFC822).   

    A ARPANET deu tão certo, que em 1982 o departamento de defesa(DOD) o abandonou o projeto de rede AUTODIN II e adotou a tecnologia ARPANET para a Rede de Dados do Departamento de Defesa. A atual MILNET, que se dividiu da ARPANET original em 1983, como o componente operacional, não classificado da rede DDN, enquanto a ARPANET continua em avanço no DARPA. Em prática, a ARPANET tb foi a rede de suporte operacional para o DOD, DOE(Dept de Energia) e alguns pesquisadores de ciências do computador patrocinados pela NSF. Esta comunidade começou a depender da disponibilidade dessa rede. Até o advento da NSFnet, o acesso à ARPANET era restrito a esses grupos.

    Como uma rede operacional na comunidade de pesquisa de engenharia e ciências e com o aumento da disponibilidade de super-minicomputadores, a ARPANET começou a ser uma ferramenta mais para o compartilhamento de informações do que de recursos. A principal lição da experiência com a ARPANET  é que o compartilhamento de informações é o principal benefício das redes de computadores. Pode se dizer que a ARPANET foi responsável por muitos avanços em sistemas de computadores e inteligência artificial.

    Porém, a ARPANET teve seu lado negativo implantando a questão "ter ou não ter" para pesquisas em computadores. Cientistas e engenheiros fazendo pesquisas fora desses lugares que tinham a ARPANET disponível, estavam em clara desvantagem no acesso a informações técnicas pertinentes e na atração de estudantes e faculdades.

    Em outubro de 1985, a NSF e a DARPA, com o apoio do DOD, assinaram um acordo para expandir a ARPANET de modo a permitir que usuários de supercomputadores da NSF pudessem usá-la para acessar o centro de recursos de supercomputadores da NSF e para se inter-comunicarem.O efeito imediato deste acordo foi permitir usuários dos supercomputadores da NSF, com uma conexão para ARPANET já existente, usá-la. Além do mais, os centros de recursos de supercomputadores da NSF das Universidades de Cornell e Illinois, estão conectados à ARPANET. Geralmente, as conexões já existentes da ARPANET estão em departamentos de ciências de computação ou de engenharia elétrica e não estão acessíveis prontamente a outros pesquisadores.

    Como uma parte da iniciatica da NSFnet, várias universidades pediram a conexão à ARPANET. Cada um destes camp se comprometeram a: estabelecer um "gateway" acessível a todos do curso e ser capaz de usar a ARPANET para acessar os centros de computação da NSF, de dentro de seu próprio ambiente de computação. Alguns outros pedidos estão sendo considerados pela NSF.

CSNET
~~~~~~

    CSNET. O estabalecimento de uma rede de pesquisas para ciências de computação foi sugerida em 1974, pelo comitê de organização de ciências de computação da NSF. O objetivo da rede seria incentivar a colaboração entre pesquisadores, oferecer compartilhamento de pesquisas e apoiar os pesquisadores isolados nas menores universidades.

    Na primavera de 1980, a CSNET(Computer Science Network) foi definida e proposta à NSF como uma rede composta de várias redes físicas de variadas forças, performances e custos. A NSF respondeu com um contrato de 5 anos para desenvolvimento da rede sob a condição de que ela seria financiamente capaz de se manter sozinha até 1986. Inicialemte a CSNET era uma rede com 5 componentes principais -- ARPANET, Phonenet, X25Net e um name server. O serviço oferecido comumente por todas essas redes é o email, que é integrado num serviço especial de host. Os usuários da CSNET podem enviar emails para todos os usuários da ARPANET e vice-versa. A CSNET, com o apoio do DARPA, instalou conexões ARPANET nos sítios de desenvolvimento da CSNET das universidades de Delaware, Wisconsin e Purdue.

    Em 1981, Bolt, Beranek e Newman(BBN), foram contratados para oferecer serviços técnicos e de usuário e para operar o Centro de Coordenação e Informação da CSNET. Em 1983, o gerenciamento geral da CSNET foi assumido pela UCAR(Univ. Corporation for Atmospherica Research), com um subcontrato com a BBN. Desde então, a CSNET tem crescido rapidamente e é atualmente independente, financialmente estável e profissional gerencia serviços à comunidade de pesquisa de computadores. Mais de 165 grupos de pesquisas de computadores de Universidades, Indústrias e governamentais, agora pertencem à CSNET.

    Várias lições foram tiradas da experiência com CSNET:

    1)    A rede é financialmente auto-suficiente, mostrando que a pesquisa deseja pagar pelos benefícios de um serviço de rede.

    2)    Enquanto consideráveis benefícios estão disponíveis para pesquisadores, a partir de email e serviços de lista, -- a Phonenet -- a maioria dos pesquisadores querem o serviço de muito mais alto nível oferecido pela ARPANET.

    3)    Oferecer serviços e informações ao consumidor é crucial, até mesmo quando eles profissionais dedicados de ciências de computação. As lições tiradas da experiência com a CSNET irã oferecer opiniões valiosas no design, implementação, oferecimento de serviços ao usuário, operação e gerenciamento da NSFnet e, principalmente, ao desenvolvimento do modelo apropriado para a NSFnet.

    A CSNET, com o apoio do programa da NSFnet, está desenvolvendo o projeto CYPRESS, que está examinando de que maneira os serviços dela podem ser melhorados a baixo custo para os departamentos de pesquisa. O CYPRESS vai usar a suíte de protocolo do DARPA e oferecerá serviços como a ARPANET em links de linhas telefônicas alugadas de baixa velocidade, de 9600 bps. A rede vai usar a topologia mais próxima da vizinhança, modelada em BITNET, enquanto oferecerá um nível mais alto de serviços aos usuários e também de interoperabilidade com a ARPANET. O projeto CYPRESS foi feito para substituir ou suplementar a rede o uso da CSNET com redes públicas X.25, que provou ser extremamente caro. Isto tb pode ser usado para oferecer uma conexão de baixo custo com a NSFnet para campus menores.

        SSTV - é similar ao Viewdata. Usado para transmitir figuras de alta-resolução misturadas com texto.

    Para começar, vc precisará comprar um receptor(com uma cobertura de não menos que 500KHz - 30MHz e uma resolução maior que 100Hz) e uma antena de alta qualidade. Os dois podem ser encontrados facilmente em lojas de eletrônica. Vc tb vai precisar de uma interface e algum software de RTTY p/ o seu computador. Procure em revistas como 'Amateur Radio" ou "Ham Radio Today" para maiores informações. Um outro bom lugar para procura seria uma loja de CB.

                                        exemplo:   'RYRYRYRYRYRYRYRYRYRYRY' etc.

    Isto é feito para que eles possam manter seus canais abertos para recepção.

    Comunicações de Telefones Móveis não é a mesma coisa que celular. O Serviço de telefonia Móvel não é tão avançado quanto o do celular, e nem tão eficiente quanto. O Serviço de Telefonia Móvel limita o número de consumidores aguçadamente, enquanto o celular foi desenvolvido para suprir estes problemas.

    O sinal para telefonia móvel é transmitido por transmissores de alta potência e antenas que oferecem uma área de 30-40Km com o serviço.

    Uma unidade base de um sistema de comunicações móveis transmite e recebe em diferentes freqüências, ao mesmo tempo. A potência típica para o transmisso da estação base de rádio é de 200-250Watts.

    As instalações da telefonia móvel são iguais às da posição fixa do sistema telefônico comum, porém, as unidades de base podem ter um Radio Common Carrier(RCC). RCCs rodando os sistemas móveis de telefonia são cobrados pela companhia telefônica pelo uso do sistema telefônico comum.

----------------------------------------------------------------------

    Como vc pode ver pelo diagrama acima, chamadas feitas pelo telefone fixo são roteadas através do CO como norrmal, através de uma rede de comutação, através de outra rede de comutação e para outro CO. A partir do segundo CO(mais próximo a unidade móvel), os sinais são mandados numa linha telefônica para o terminal de controle, para o receptor e, então, para a unidade de base(antena). A partir da unidade de base, os sinais são mandados para o sítio do telefone móvel.

    As chamadas feitas pelo telefone móvel operam da mesma maneira. Um canal ocioso de rádio é escolhido(como um rompimento de um calção para uma ligação de LD) e os sinais mandados através da rede móvel.

    Se nenhum canal estiver disponível para uso, um sinal de ocupado é mandado. Se um canal estiver disponível, o consumidor escutará um tom de discagem, similar à posição normal do serviço de telefone fixo.

    A área que isto funcionaria é chamada de área do lar do assinante. Quando um assinante do serviço móvel de telefone deixa sua área de serviço, ele é referido como um "Roamer". Como a unidade móvel está fora da área de serviço, preparações especiais precisam ser feitas para as comunicações com aquela unidade móvel continue.

 

SINALIZAÇÃO
------------------

    A sinalização de tons móveis são escolhidas(como Touch Tones) para evitar possível reprodução do tom no link de voz, que causa falha na sinalização. O IMTS (Improved Mobile Telephone Service) usa bandas de sinalização de 1300Hz a 2200Hz. Outro método de sinalização é o MTS (Mobile Telephone System). O MTS é mais velho que o IMTS, e usa tons de sinalização de 600Hz a 1500Hz, alguns usam 2805Hz em operação manual.

COMPLETAÇÃO DE CHAMADA
--------------------------------------

    Neste caso, vamos dizer que a chamada foi feita de um telefone normal para um unidade móvel. Para começar, a estação de base escolhe um canal ocioso e coloca um tom de 2000Hz nele. Todas as unidades móveis ativas no gancho, naquela área de serviço, encontram e travam no canal que tem o tom ocioso de 2000Hz. Agora, cada unidade móvel espera pelo seu número específico naquele canal. Qdo um canal ocioso fica ocupado, um novo canal é escolhido para o uso e o processo se repete.

    Agora, a chamada é mandada pela rede telefônica da mesma maneira que uma chamada normal. Qdo esta ligação alcança o terminal de controle, o terminal quebra o já marcado canal ocioso(com toda unidade móvel esperando por ele) e aplica o tom de 1800Hz. Este tom evita que outras unidades móveis usem o mesmo canal para fazer chamadas. O número chamado é "pulsado" para o transmissor da estação de base à 10 pulsos por segundo, com o tom de ocioso representado por uma marca e o de ocupado por um espaço.

    Como cada unidade móvel no gancho está escutando aquele canal, eles comparam o número sendo "pulsado" com o seu próprio número. Se o primeiro número da unidade chamada for 3, e uma unidade móvel específica no canal tiver o primeiro dígito 4, esta unidade pára de escutar no canal e vai para o próximo canal que tiver o tom de 2000Hz.

    Qdo a unidade móvel o número de destino correto, todas as outras unidades móveis páram de escutar neste canal. Qdo o sétimo dígito é recebido, a unidade móvel de supervisão liga o transmissor móvel e manda um sinal de entendimento(um tom de guarda de 2150Hz) de volta para o terminal de controle. Se o sinal não for recebido 3 segundos depois, o tom de ocupado é retirado do canal e a ligação cai. Se o sinal for recebido no terminal de controle, o telefone móvel vai tocar (o padrão 2 segundos ligado e 4 desligado). Se unidade móvel sendo chamada não atender em 45 segundos, a ligação cai.

    Qdo a pessoa atende o telefone móvel e o tira do gancho, unidade móvel de supervisão manda um tom de conexão de 1633Hz para um sinal de resposta. Qdo ele é recebido pelo terminal de controle, o fone pára de tocar e um caminho de voz é estabelecido entre os dois telefones. Qdo o assinante móvel desliga, um sinal de desconexão é mandado(consiste em tons de desconexão/guarda de 1336Hz e 2150Hz, respectivamente). Então a unidade móvel começa novaamente a procurar por um outro canl ocioso e se prepara para mais chamadas.

    Para uma ligação feita pelo assinante Móvel, a unidade já tem que estar travada no canal ocioso. Se ela não estiver, uma luz de aviso vai piscar avisando o usuário do problema. Se a unidade já estiver travada no canal, o número discado será mandado ao terminal de controle, para propósito de cobrança.


TELEFONE CELULAR
-------------------------

    Para sair dos problemas do serviço de telefone móvel, tais como poucos usuários, preço alto, etc. a AT&T inventou o Conceito Celular ou o AMPS(Advanced Mobile Phone Service). Este é o conceito de telefone celular usado nas cidades grandes como Los Angeles, Ca, atualmente com o maior sistema de comunicação celular no mundo.

    Ligações mandadas para um telefone celular são enviadas através do MTSO(Mobile Telecommunications Switching Office). O MTSO cuida de todas as chamadas feitas a partir de um e para um telefone celular e tb da cobrança.

    Todas as chamadas vindas do MTSO para o sítio do Celular em cada célula, para o telefone celular. A maior diferença entre telefones móveis e celulares é que o celular pode usar o mesmo canal muito mais vezes do que um móvel pode, oferecendo mais consumidores e deixando o serviço mais barato.

    Se um veículo sai do sítio celular, o sinal é transferido imediatamente, sem perda de sinal, para outro sítio celular, onde a ligação continua sem interrupção. Isto se chama "Cellular Hand-off".

    As áreas de comunicação celular são divididas em várias células, como um colméia.

    Mais sítios celulares são usados para a área que são precisos. São sinais são enviados pelo MTSO para cada sítio. Então, se vc estivesse viajando pelo sítio mais a esquerda, o sinal do MTSO seria mandado para aquela célula.

    Dirigindo de célula em célula, equipamentos eletrônicos sofisticados transferem a ligação para outra célula. Esta seqüênciaa automática mantém a qualidade do serviço sem interrupção na conversação.
